WHAT CHANGED, AND WHY
---------------------

Four fixes, all from your notes.

1. Tones now only play when YOU switch keep-alive on or off. The
   automatic release, and the automatic wake when you next type, are
   both silent. This is not a setting - it is simply how it works now.

2. "mouse off" now actually works. The bug was not the trackpad sweep,
   which was being recognised correctly. It was the moment your finger
   came OFF the pad. That is itself an input event, and it arrives
   after the pointer has already stopped moving - so it looked exactly
   like a keypress. The app now waits for the pointer to have been
   still for half a second before it will call anything the keyboard.

3. The tray menu should work from the keyboard. It was never a menu
   problem: the icon had never asked Windows for the newer notification
   protocol, and the older one only ever tells a tray icon about mouse
   buttons. Enter and the Applications key were producing no message at
   all. That has been rebuilt rather than patched, so please treat the
   whole tray as untested again.

4. The tones are quieter and shorter, to your figures - volume 0.1, and
   about a fifth shorter. The on-tone now starts with a quarter second
   of silence, so the Bluetooth link has time to come up before the
   tone begins. That quarter second is a guess. Test 20 asks about it.

Also: switching off should be a little quicker than last time.

TEST 22 - MOUSE OFF, AND MOUSE ON
===========================================================

Two things here. The first is the fix. The second is something we
still have never actually seen work, because last time the step that
would have shown it came after an "off" command, and switching off by
hand deliberately stops the keyboard waking it too.

So this time, do NOT type "off" - let the timeout do the releasing.

Steps:

1. Type: idle 10
2. Type: mouse off
3. Press the hotkey to switch keep-alive on.
4. Sit quietly for about fifteen seconds so it releases on its own.
   (Silently, now.)
5. Move the trackpad - a good deliberate sweep - and do not touch any
   key at all afterwards.

ANSWER - did keep-alive stay off? It should. The console will print a
line if it came back on, and the log will say "woken by keyboard
input".

6. Wait a few seconds, still not touching the keyboard, and sweep the
   trackpad again. Try a short flick as well as a long sweep.

ANSWER - still off?

7. Now press a key.

ANSWER - did keep-alive come back on?

8. Type: mouse on
9. Press the hotkey to switch keep-alive on, then sit quietly for
   fifteen seconds again so it releases on its own. Do not type "off".
10. Move the trackpad without touching a key.

ANSWER - with "mouse on", did the trackpad wake it this time? This has
never actually been confirmed to work.

11. Type: mouse off

ANSWER - over a few minutes of normal work with "mouse off", did the
trackpad ever wake it when you did not mean it to?

ANSWER - did anything you did with the keyboard ever FAIL to wake it?
The half-second settling window means a keypress very shortly after
moving the pointer is ignored, and I would like to know if that is
noticeable.
